# 운영 매뉴얼 (계획서 Step 8)

관리자 화면 `https://{도메인}/admin.html` 에서 매일 하는 일과, 문제가 났을 때 하는 일을 순서대로 적는다.
배포·환경변수·백업 복구 명령은 [README](../README.md#배포--flyio), 런칭 당일 점검은 [런칭 체크리스트](launch-checklist.md).

- 관리자 화면은 토큰(`ADMIN_TOKEN`)을 넣고 "불러오기". 토큰은 그 탭의 sessionStorage 에만 남는다(탭을 닫으면 사라짐) — 공용 PC 에서는 쓰고 나서 탭을 닫는다.
- 탭(목록): **검수 대기** · **붙어 있음** · **떼어 냄** · **환불 필요** · **환불 완료** · **입금 대기**. 맨 위에 **최근 문제**, 아래에 **관리 기록**(감사 로그).
- 관리 작업(붙이기·거절·떼어 내기·다시 붙이기·고치기·환불 완료·CSV 내려받기)은 전부 관리 기록에 남는다 — 누가(가린 IP + 토큰 지문 8자리)·언제·무엇(주문번호 앞 8자리).

## 하루 점검 (5분)
1. 최근 문제 칸 — 비어 있으면 통과. 있으면 아래 [장애 대응](#장애-대응) 표대로
2. 검수 대기 — 0건이 될 때까지 처리(광고주는 입금하고 기다리는 중)
3. 붙어 있음 — "신고" 숫자가 있는 광고 확인, 떼어 냄 — 자동으로 떼어진 광고 확인([신고 처리](#신고-처리))
4. 환불 필요 — 0건이 될 때까지 처리([환불 처리](#환불-처리))
5. 관리 기록 — 내가 하지 않은 작업이 있는지(모르는 토큰 지문·IP 가 보이면 [관리자 토큰 교체](#관리자-토큰-교체) 즉시)

## 검수
### 주문이 검수 대기로 오는 길
- 신청 단계에서 먼저 걸러진다(관리자에게 오지 않음): 이름 필터(길이·금칙어·이름 속 링크·전화번호), 이미지 형식·크기, 이동 주소 형식(공개 http(s) 주소만), 분류기 "거절".
- 입금이 확인되면 분류기 판정이 "검토"였던 주문만 **검수 대기**로 가고, 나머지는 바로 **붙어 있음**(출연)이 된다.
- 칸 추가 주문은 이미 검수된 광고라 다시 검수하지 않는다.

### 모드별 차이 (`MODERATION_MODE`)
| 모드 | 이미지 광고 | 이동 주소 있는 광고 | 텍스트만 | 관리자 부담 |
|---|---|---|---|---|
| `review-all`(기본) | 전부 검수 대기 | 검수 대기 | 바로 출연 | 이미지 광고 전부를 사람이 본다 |
| `vision` | adult·violence·racy 중 하나라도 LIKELY 이상 → **신청 단계에서 거절**(입금 전, 돈이 오가지 않음). POSSIBLE·UNKNOWN 또는 **얼굴 감지** → 검수 대기. 나머지 → 바로 출연 | 검수 대기 | 바로 출연 | 애매한 것·얼굴·이동 주소만 본다 |
| `auto-approve` | 전부 출연 | 전부 출연 | 바로 출연 | **운영 모드에서는 시작 거부** — 로컬 데모 전용 |

- `vision` 에서 API 오류·타임아웃(8초)·이상한 응답은 전부 **검수 대기**로 떨어진다(열린 채 승인하지 않는다). Vision 장애가 길면 검수 대기가 쌓이니 그때는 사람이 다 본다.
- Vision 은 이미지 속 글자(OCR)를 보지 않는다 — 로고 안 문구는 사람이 본다.

### 승인·거절 판단 기준
검수 대기 목록에서 로고(원본 색)·광고 이름·이동 주소를 보고 정한다.

| 판단 | 이럴 때 | 버튼 |
|---|---|---|
| **붙이기**(승인) | 아래 거절 사유가 하나도 없음 | `붙이기` → 붙어 있음, 게임에 바로 나온다 |
| **거절** | ① 선정적·폭력적·혐오 이미지/문구 ② 실존 인물 얼굴·사진(본인 동의 확인 불가) ③ 남의 상표·로고를 광고주가 아닌 사람이 올린 것으로 보임 ④ 이동 주소가 도박·성인·불법 판매·피싱·악성 사이트 ⑤ 불법 상품·서비스 광고 ⑥ 정치·선거 광고, 특정인 비방 | `거절·환불` → 환불 필요로 간다([환불 처리](#환불-처리)) |
| **고쳐서 붙이기** | 이름 오타·이동 주소 오기처럼 광고주 의도가 분명한 사소한 문제 | `고치기`(이름·이동 주소·로고, 칸 수·금액은 못 바꿈) → `붙이기` |

- 애매하면 거절이 아니라 **보류**(목록에 그대로 둠)하고 신청서의 연락처로 광고주에게 묻는다. 입금 뒤 오래 붙지 않으면 광고주가 문의하므로 하루 안에 결론을 낸다.
- 거절 이유는 광고주에게 직접 알린다(화면에 자동 안내 없음).

## 신고 처리
- 게임 사망 카드의 "신고"로 들어온다. 사유: 권리침해(`rights`)·음란(`obscene`)·혐오(`hate`)·기타(`other`). 같은 사람(접속 IP 해시)은 한 광고에 한 번만 센다.
- **자동 떼어 냄**: ① **권리침해 신고 1건 즉시**(정보통신망법 44조의2 임시조치) ② 그 밖의 사유는 **서로 다른 신고자 3명 누적**. 떼어 낸 광고는 **떼어 냄** 탭으로 가고 게임·장부에서 빠진다(확률 계산에서도 빠짐).
- 관리자 확인:
  1. **떼어 냄** 탭에서 신고 수·권리침해 여부를 보고 광고를 다시 본다
  2. 문제 있음 → `삭제·환불`(환불 필요로 감). 권리침해가 맞으면 신고자에게 처리 결과를, 광고주에게 삭제 사유를 알린다
  3. 문제 없음(장난 신고) → `다시 붙이기` — 신고 기록이 비워지고 다시 출연한다. 권리침해 임시조치였다면 광고주에게 소명을 받은 뒤에 붙인다(임시조치 기간은 법령상 30일 이내)
- 붙어 있음 탭에서 신고 수가 쌓이는 중인 광고(아직 3명 미만)는 미리 보고 직접 `떼어 내기` 해도 된다.
- 떼어 낸 광고에 칸 추가 입금이 늦게 도착하면 붙이지 않고 그 주문은 환불 필요로 간다(자동).

## 환불 처리
환불은 **PG 환불 API 를 부르지 않는다** — 돈은 사람이 돌려주고, 서버에는 "돌려줬다"는 기록만 남긴다.

### 환불 필요가 생기는 조건
| 조건 | 어떻게 |
|---|---|
| 입금 기한(가상계좌 발급 뒤 24시간)이 지나서 입금됨 | 입금 확인 시 자동 |
| 입금 사이에 판매 한도(1,000,000칸)를 넘김 | 입금 확인 시 자동 |
| 칸 추가 입금 사이에 원래 광고가 떼어졌거나 내려감 | 입금 확인 시 자동 |
| 관리자가 거절·삭제 | 검수 대기·붙어 있음·떼어 냄에서 `거절·환불`/`삭제·환불` |

### 순서
1. **환불 필요** 탭에서 주문(주문번호 앞 8자리·광고 이름·금액·입금 일시)을 확인한다
2. 실제 환불을 **사람이** 한다 — 토스페이먼츠 상점관리자에서 그 주문의 결제 취소(가상계좌 환불 계좌 입력), 또는 광고주에게 받은 계좌로 직접 이체. 어느 쪽이든 PG/은행의 처리 내역(취소 번호·이체 확인)을 남긴다
3. 관리자 화면에서 그 주문의 **`환불 완료 처리`** — 처리 일시(실제 돌려준 시각)와 메모(예: "상점관리자 취소, 국민 이체 확인")를 넣는다.
   환불 필요 → 환불 완료만 가능하고 **되돌릴 수 없다** — 돈이 실제로 나간 뒤에만 누른다. 메모는 200자까지
4. **환불 완료** 탭에서 `이 목록 CSV로 내려받기` → 월별로 파일을 보관한다(세무·분쟁 대응). 파일 이름 `ad-dodge-orders-YYYYMMDD-refunded.csv`, 엑셀에서 바로 열린다(UTF-8 BOM)
- CSV 에는 주문번호 앞 8자리만 들어간다(전체 주문번호는 주문 조회 권한이라 내보내지 않음). 결제 secret·paymentKey 는 들어가지 않는다.
- 장부를 백업에서 되돌린 경우 백업 시각 뒤의 입금은 장부에 없다 — 토스 결제 내역으로 찾아 같은 순서로 돌려주고, 기록은 별도 문서에 남긴다([README 복구 뒤 맞춰 보기](../README.md#복구-뒤-맞춰-보기-세-갈래-공통)).

## 장애 대응
### 최근 문제 — 종류별 조치
관리자 화면 맨 위 "최근 문제"(최근 50건, 메모리 — 서버가 다시 뜨면 비워짐). 원문 전체는 `fly logs` 에 있다.

| 종류 | 뜻 | 조치 |
|---|---|---|
| `server` | 요청 처리 중 500 오류(경로·오류 문구) | 같은 경로가 반복되면 `fly logs` 에서 그 시각 오류를 찾는다. `/api/health` 가 503 이면 장부를 못 읽는 상태 → [README 백업과 복구](../README.md#백업과-복구). 한두 건이면 지켜본다 |
| `webhook` | 웹훅 검증 실패(우리 주문 아님·secret 불일치·금액 불일치) | 입금 한 건에 한 줄이면 보통 위조·잘못된 요청이라 조치 없음. 실제 입금인데 반영이 안 됐다는 문의가 오면: 토스 개발자센터 웹훅이 **`DEPOSIT_CALLBACK` 하나만** 등록돼 있는지, 주소가 `https://{도메인}/api/payments/webhook` 인지 확인. 금액 불일치는 광고주가 다른 금액을 넣은 것 → 토스 결제 내역 확인 후 환불 |
| `pg` | 토스 API 장애(가상계좌 발급 실패·웹훅 때 결제 조회 실패) | 조회 실패는 503 을 돌려줘서 토스가 재전송한다(최대 7회) — 대개 저절로 풀린다. 계속되면 [토스 상태](https://developers.tosspayments.com)·`TOSS_SECRET_KEY`(만료·테스트/운영 키 혼동) 확인. 발급 실패 중에는 주문이 남지 않으므로 광고주는 다시 신청하면 된다 |
| `backup` | 1시간 백업 실패(로컬 복사 또는 외부 S3 업로드) | 로컬이면 볼륨이 꽉 찼는지(`fly ssh console -C "df -h /data"`). 외부면 S3 키 만료·버킷 권한·엔드포인트 확인 → `fly secrets set BACKUP_S3_…`. 서버는 멈추지 않는다. 고치는 동안은 `fly volumes snapshots create {볼륨 id}` 로 수동 스냅샷 |
| `admin` | 관리자 토큰 실패 반복으로 그 IP 를 15분 차단 | 내가 오타를 낸 거면 15분 기다린다. 아니면 누군가 토큰을 맞추려는 중 → 관리 기록에 모르는 작업이 없는지 보고, 의심되면 [관리자 토큰 교체](#관리자-토큰-교체) |
| `audit` | 관리 작업은 됐는데 관리 기록(감사 로그)을 못 씀 | 장부 쓰기 문제일 가능성 — `server`·`backup` 도 같이 보이는지, 볼륨 용량 확인. 그 작업은 따로 메모해 둔다 |

### 관리자 화면이 429(요청이 너무 많아요)일 때
- **분당 120회 초과**(IP별): 1분 안에 풀린다 — 새로고침을 멈추고 1분 기다린다.
- **토큰 실패 5분 안에 10회 초과**: 그 IP 가 **15분** 차단된다(최근 문제 `admin`). 15분 뒤 올바른 토큰으로 다시. 급하면 다른 네트워크(휴대폰 테더링 등)에서 접속하거나,
  차단 목록은 메모리에만 있으므로 `fly machine restart {머신 id}` 로 풀 수 있다(재시작 중 몇 초 사이트가 끊긴다).
- 게임 쪽 요청(주문 분당 5회·신고 분당 10회·헬스체크 분당 30회 등)도 1분 단위로 풀린다.

### 사이트가 안 열릴 때
1. `fly status` — 머신이 `started` 인지, 체크가 통과인지
2. `fly logs` — `[config]` 줄이 있으면 환경변수 문제(그 이름을 `fly secrets set`), `저장소 파일을 읽을 수 없습니다` 면 장부가 깨진 것 → README 복구 1
3. 고쳤으면 `/api/health` 200 확인

## 관리자 토큰 교체
정기(분기마다)·관리자가 바뀔 때·유출이 의심될 때(모르는 관리 기록, `admin` 차단 반복) 바꾼다.
1. 새 토큰을 만든다: `openssl rand -hex 32` → 출력값을 **먼저** 비밀번호 관리자에 저장(이 문서·메신저·이슈에 붙이지 않는다)
2. 넣는다: `fly secrets set ADMIN_TOKEN={새 토큰}` — 머신이 새 값으로 다시 뜬다(몇 초 끊김). 운영 모드 규칙(32자+·문자 10종+·자리표시 낱말 금지)에 걸리면 시작이 거부되고 `fly logs` 에 `[config] ADMIN_TOKEN 이 약합니다` 가 남는다 → 다시 만든다
3. 확인: `fly logs` 에 `[server]` 시작 줄 → 관리자 화면 탭을 닫았다 새로 열고 새 토큰으로 "불러오기". 옛 토큰은 401 이어야 한다
4. 관리 기록의 토큰 지문(8자리)이 바뀐다 — 교체 일시와 새 지문을 운영 메모에 적어 두면 "어느 토큰으로 한 작업인지" 구분된다
5. 유출 의심이었다면: 교체 전 관리 기록에서 모르는 지문·IP 의 작업을 찾아 되돌린다(잘못 떼어진 광고는 `다시 붙이기`, 잘못 붙은 광고는 `거절·환불`)

다른 비밀값도 같은 방식(`fly secrets set 이름=값`)으로 바꾼다 — 토스 키는 상점관리자에서 재발급 후, S3 키는 저장소에서 새 키를 만든 뒤 옛 키를 폐기.
