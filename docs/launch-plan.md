## 위험 판단

- **PG 반려 위험 (높음)**: 심사관이 "확률로 광고가 나온다 + 결제"를 사행성으로 오해할 수 있다. 대응: 상품을 "광고 게재(칸) 판매"로 명확히 쓰고, 현금·경품 없음, 확률 공개, 환불 규정을 사이트에 미리 노출. 필요하면 업종 설명서 첨부.
- **등급분류 (중간)**: 무료 웹게임이라도 상업적으로 서비스하면 대상. 출시 전 게임위 신청(또는 위탁기관). 결과 나오기 전엔 "시험용·비공개 테스트"로만.
- **유료 광고가 유일한 매출**: 광고주가 0명이면 하우스 광고만 날아감 → 런칭 첫 주 시딩 광고주(지인·소상공인) 확보가 별도 과제.

## 코드 단계

### Step 1 — 사이트 법정 표시: 사업자 정보 푸터·개인정보처리방침·약관 보강 · ✅ 완료
사업자 정보를 환경변수(BIZ_NAME, BIZ_OWNER, BIZ_REG_NO, BIZ_ADDRESS, BIZ_PHONE, BIZ_EMAIL, BIZ_MAIL_ORDER_NO, HOSTING_PROVIDER)로 받아 시작 화면·약관·신청서 하단에 표시하고, 비어 있으면 운영 모드에서 서버가 시작을 거부한다. 개인정보처리방침 페이지(privacy.html)를 만들어 수집 항목(IP 해시, 접속 기록, 업로드 이미지, 입금 정보)·보유 기간·파기를 적는다. 약관의 TODO를 치환식으로 바꾼다.
- 인수 조건: 운영 모드에서 사업자 정보 누락 시 서버 시작 실패 테스트 / 시작·약관·신청서에 사업자 정보와 처리방침 링크가 보인다 / 사용자 문자열은 textContent로만 들어간다
- 범위 밖: 실제 사업자 정보 값 입력(H1 이후 사람이 넣음)

### Step 2 — 실제 PG 연동: 토스페이먼츠 가상계좌 provider · ✅ 완료
`server/payments.js`의 인터페이스(issueVirtualAccount·verifyWebhook)를 그대로 구현하는 토스페이먼츠 provider를 추가한다. 공식 문서로 가상계좌 발급 API와 웹훅(입금 확인) 검증 방식을 확인하고, 웹훅은 서명/시크릿 검증 후 결제 조회 API로 금액·상태를 재확인한다. PAYMENT_PROVIDER=toss|mock 으로 고르고, 시크릿 키는 환경변수로만 받는다.
- 인수 조건: 문서의 샘플 응답으로 발급·웹훅 파싱 단위 테스트 / 위조 웹훅·금액 불일치 거부 / 멱등(같은 웹훅 2회) 유지
- 범위 밖: 카드 결제·부분 환불 API 자동화

### Step 3 — 이미지 AI 검수: Google Vision SafeSearch + 얼굴 감지 분류기 · ✅ 완료
`server/moderation.js`의 classifier 인터페이스로 Vision 분류기를 추가한다. SafeSearch(adult·violence·racy)가 LIKELY 이상이면 reject, POSSIBLE이면 review, 얼굴이 감지되면 review(초상권). API 실패·타임아웃이면 review로 떨어진다(열린 채 실패 금지). MODERATION_MODE=vision 으로 선택.
- 인수 조건: 가짜 Vision 응답으로 approve/review/reject 분기 테스트 / API 오류 시 review / 키는 환경변수만
- 범위 밖: 이미지 속 글자(OCR) 욕설 검사

### Step 4 — 배포 구성: 컨테이너·영구 볼륨·HTTPS·헬스체크 · ✅ 완료
Dockerfile(node:20-alpine, 비root 사용자)과 fly.toml(DATA_DIR=/data 볼륨, 내부 포트, 헬스체크 /api/health)을 만들고, /api/health 엔드포인트, 운영 필수 환경변수 시작 검증(ADMIN_TOKEN 32자+, WEBHOOK/PG 시크릿, DEV_DEPOSIT·FREE_MODE 금지), TRUST_PROXY 기본값, 종료 시그널에서 lazy 쓰기 flush를 보장한다.
- 인수 조건: 운영 모드에서 DEV_DEPOSIT=1 또는 FREE_MODE=1이면 시작 거부 테스트 / /api/health 200 / 로컬 docker build·run으로 게임·관리자 동작
- 범위 밖: 다중 인스턴스(파일 저장소라 단일 인스턴스 전제)

### Step 5 — 운영 기능: 환불 처리 기록·외부 백업·오류 알림 · ✅ 완료
관리자 "환불 필요" 목록에 환불 완료 처리(일시·메모)와 CSV 내보내기를 추가하고, 백업을 볼륨 밖(선택: S3 호환 저장소)으로도 보낼 수 있게 하며, 500 오류·웹훅 실패를 관리자 화면 상단에 모아 보여준다.
- 인수 조건: 환불 완료 상태 전이 테스트(환불 필요 → 환불 완료만 허용) / CSV 내보내기 헤더·인코딩(BOM) 테스트 / 오류 집계 표시
- 범위 밖: PG 환불 API 자동 호출

### Step 6 — 보안 마무리: 관리자 인증 강화·감사 로그·보안 리뷰 · ✅ 완료
관리자 토큰 강도 검증, 관리자 엔드포인트 전용 레이트 리밋, 관리자 작업(승인·거절·수정·환불) 감사 로그(누가·언제·무엇)를 남기고, 전체 보안 리뷰(OWASP·CSP·업로드·웹훅·레이트 리밋 우회)를 다시 돈다.
- 인수 조건: 관리자 무차별 대입 시 429 / 감사 로그 기록·조회 테스트 / 보안 리뷰 CRITICAL·HIGH 0건

### Step 7 — 실기기·E2E 테스트 체크리스트 · ✅ 완료
핵심 흐름(시작 → 플레이 → 사망 카드 공유/저장 → 도전장 → 광고 붙이기 → 입금 → 출연 → 신고 → 관리자 가림)을 브라우저 자동화 E2E로 만들고, 인스타 인앱·iOS 사파리 수동 확인 체크리스트를 문서로 남긴다.
- 인수 조건: E2E가 로컬 테스트 모드에서 통과 / 실기기 체크리스트 문서(항목·기대 결과·확인 칸)
